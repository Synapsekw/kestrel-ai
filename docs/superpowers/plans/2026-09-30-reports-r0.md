## Global Constraints

- `contract/openapi.yaml` is the source of truth. `contract/client/schema.d.ts` is regenerated with `pnpm -C contract generate` and committed in the **same commit** as the YAML. Never hand-edit it.
- R0 edits only the `reports` tag's paths and schemas, plus these shared lines, each **append only**: the top-level `tags:` list, `components.parameters`, the `JobType` enum, the `Job.result` description, the `Error.code` description, and the `DetectExportRequest.format` property (the deprecation).
- **No `default:` in any Reports schema.** A request property's default goes in its `description` (ADR `2026-09-20-gotcha-openapi-default-makes-a-field-required-in-typescript`). Every response property is `required`, and nullable where it can be empty.
- In a YAML flow mapping (`{ ... }`), a `description` is always double-quoted (ADR `2026-09-26-gotcha-yaml-flow-mapping-comma-splits-a-description`). Every description below is already quoted; keep them exactly.
- Every new operation has `tags: [reports]` and `default: { $ref: "#/components/responses/Error" }`, and answers 501 `not_implemented` until its owner lands.
- Names are exactly as written here: operationIds, paths, path-parameter names, schema names, property names, enum values and Python names. Every other R unit codes against them.
- **Pydantic models express exactly what the contract expresses, and nothing more.** There are no cross-field validators. A rule the schema cannot state is refused by the owning unit with its own code (`invalid_report`, `invalid_template`), never `validation_error` (`tests/test_contract.py`, `REFUSES_VALID_DATA`).
- Config and request models forbid extra keys (`additionalProperties: false`). The config models carry the defaults of a new report.
- reportlab and openpyxl are never imported by anything R0 adds.
- Migrations: project `backend/app/db/migrations/versions/0014_reports.py`, `revision = "0014"`, `down_revision = "0013"`. Catalogue `backend/app/catalogue/migrations/versions/0002_report_templates.py`, `revision = "0002"`, `down_revision = "0001"`. Neither imports `app.*`: each carries frozen copies of its checks and seed data.
- Shared interpreter `E:\Dev\Yolo\app\backend\.venv\Scripts\python.exe` (`$PY`). No package is installed.
- Stage by path. Never use `git add -A`, `git add .` or `git commit -a`. Every commit message ends with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Rulings (taken while planning; reviewers should not flag them)

1. **Stubs live in the owner's route module; `EXPECTED_STUBS` is derived.** Each of `routes_reports.py`, `routes_templates.py`, `routes_assets.py`, `routes_open.py` (R1), `routes_outline.py` (R2), `routes_snapshots.py` (R3) and `routes_versions.py` (R5) exports `router` and a `STUBS` list. `app/reports/router.py::stub_operation_ids()` collects them, and `tests/test_contract.py` does `EXPECTED_STUBS |= reports_stub_operation_ids()` (M-C0's pattern). An owner rewrites its module and drops `STUBS`, and nothing else changes. This satisfies R1's and R5's "whatever form R0 used".
2. **A config always lists all eight sections, each exactly once.** Order is print order, and `enabled` toggles a section. The contract says `minItems: 8, maxItems: 8`. Uniqueness and "an enabled cover is first" cannot be expressed, so they are R1's `invalid_report` / `invalid_template` (R1 Ruling 3).
3. **Date filter keys are `rule, from, to, days`,** as in the spec and R1. `from` is a Python keyword, so the pydantic attribute is `from_` with `alias="from"` and `populate_by_name=True`. Configs are dumped with `by_alias=True` (R1 Global Constraints).
4. **`report_version.number` is nullable** (R5 Ruling 1). The row is inserted as `rendering` with no number, and `promote` writes the number. The unique index `(report_id, number)` allows many NULLs. `label` and `error` live in `stats`, not in columns (R5 Rulings 4 and 10). `ReportVersionStats` is `{finding_count, page_count, part_count, warnings, label, error}`, and every key except `warnings` is nullable, because a rendering row has only `label`.
5. **The version document is paged across sections** as R5 builds it: `ReportDocumentPage {report_id, version, generated_at, theme_version, sections, next_cursor}`, with ≤ 50 blocks per page and a section split across pages repeating its key.
6. **The cover is one `cover` block** (coordinator message; plans R2 ruling 2, R4 ruling 4): `CoverBlock {kind: cover, title, subtitle, rows, logo, locator}` with `logo: CoverLogo {asset_id, path, width_px, height_px} | null` (the path is project-relative, forward slashes) and `locator: Figure | null` (a `map` SnapshotRef figure). The rows carry Project, Site, Client, Author, Report date, Period, Version and Status. R2 fills it, R4 draws the band, logo and locator from it (resolving `path` against the project), and R6 renders it in the preview. A missing logo row or file gives `logo: null` and the warning `logo_missing`. This amends the index's block list (twelve kinds). There is no logo snapshot kind. The live preview loads the logo from `GET /projects/{projectId}/report-assets/{assetId}` (`getReportAsset`, R1, coordinator ruling) using `CoverLogo.asset_id`.
7. **Error codes are R1's and R5's:** `invalid_report` and `invalid_template` (422, details `{errors: [{path, message}]}`), `builtin_template` (409), `asset_invalid` (422, details `{reason}`, also for over 20 MB), `render_running` (409, details `{job_id}`), `issued_version` (409). R3's are `invalid_snapshot_spec` and `snapshot_key_mismatch` (400). `POST /open` answers 409 `conflict` for a folder, a path outside the project, or a suffix not in R1's allow-list (R1 Ruling 11).
8. **Shapes follow R1:** DELETE of a report is 204 (it archives or deletes); duplicate has no body; `ReportPatch` is `{title?, config?}` (no unarchive, R1 Ruling 5); `last_version.number` is nullable (the newest row may be rendering or failed, R1 Ruling 4); a template `name` is 1–120 characters. `openProjectFile` reuses `RevealRequest {path}`, relative to the project folder.
9. **`report_render` job:** params `{report_id, version_id, formats, label}`, result `{version_id, number, folder, files}` (R5). R0 adds only the name to `JobType` and the frontend labels. R5 registers the job and its offline seam.
10. **The detect PDF is deprecated at the enum value, not the operation.** `DetectExportRequest.format` becomes `oneOf: [{const: csv}, {const: pdf, deprecated: true}]`. The generated TypeScript type stays `"csv" | "pdf"` (verified with openapi-typescript 7.13), and `test_transition_allowances_name_real_operations` is untouched, because that test only reads operation-level `deprecated`.
11. **Additions to the spec's shapes**, each needed by a consumer:
    - `ReportDocument.paper` (`ReportPaper`, copied from the config by R2, so R4 and R6 honour Letter; coordinator message).
    - `ReportOutline.deltas` (the summary strip in the live preview).
    - The `cover` block and `CoverLogo` (Ruling 6).
    - Block and spec class names follow the consumers' plans: `Heading`, `Para`, `Kv`, `Kpis`, `Table`, `Figure`, `FigureRow`, `Chart`, `Comment`, `FindingBlock`, `PageBreakBlock`, `VolumeBlock`, `CoverBlock`; `ImageCropSpec`, `MapSpec`, `ElevationSpec`, `PairSpec`, `View3dSpec`, `VolumePlanSpec`, `AttachmentSpec` (R9-I, R9-M, R9-C, R5).

    - `ReportListItem.archived` and `.created_at` (R1's `_fields`).
    - `ImageCropSpec.annotation_id` (§9.1 keys on the annotation's `updated_at`).
    - `ElevationSpec.overlay_item_id` (§9.1 `diff(item_b)`).

## Deviations from the spec

- §19 R0a/b/c: one R0 for all of §14 (index ruling 1).
- §14 path parameters are named `reportId`, `sectionKey`, `versionNumber`, `snapshotKey`, `templateId` (the contract's camelCase convention). Where the spec writes `{n}`, the contract has `{versionNumber}`.
- §6.1 `report_version`: `number` is nullable; `label` and `error` go in `stats` (Ruling 4). `report_asset` gets `created_at` and a unique `sha256` (R1 Ruling 10: re-import is idempotent). `report_version_finding.finding_id` has no FK, because a baseline must outlive a deleted finding.
- §8.1 block kinds: + `volume` (index) and + `cover` (coordinator, Ruling 6); the cover's gradient band and logo live in that block. §9.1 snapshot kinds: + `attachment` (index).
- `ReportDocument` has no `title` or project name of its own: R4 reads them from the cover block (R4 ruling 5).
- `contract/.spectral.yaml` gains an `oas3-unused-component` override for `ReportDocument`: it is the frozen `document.json` shape and a shared fixture, but no operation returns it whole (versions page it as `ReportDocumentPage`).
- §7.1 `sections`: always eight entries (Ruling 2).
- §13 "marked deprecated": done at the enum value (Ruling 10).

def _phantom_keys(node, path):
    """An unquoted comma in a flow-mapping description makes a None-valued key with a space."""
    found = []
    if isinstance(node, dict):
        for k, v in node.items():
            if v is None and isinstance(k, str) and " " in k:

            found += _phantom_keys(v, path + [k])
    elif isinstance(node, list):
        for i, v in enumerate(node):
            found += _phantom_keys(v, path + [i])
    return found

"""Reports (spec 2026-09-26-reports section 14): one router over the per-owner route modules.

def _module():

def _cfg(url: str) -> Config:
    cfg = Config(str(MIGRATIONS / "alembic.ini"))
    cfg.set_main_option("script_location", str(MIGRATIONS))
    cfg.set_main_option("sqlalchemy.url", url)

def _run(data_dir: Path, fn) -> None:
    root = catalogue_root(data_dir)
    root.mkdir(parents=True, exist_ok=True)
    url = f"sqlite:///{(root / 'catalogue.db').as_posix()}"
    engine = create_engine(url)
    try:
        with engine.begin() as conn:
            cfg = _cfg(url)
            cfg.attributes["connection"] = conn
            fn(cfg, conn)
    finally:
        engine.dispose()

"""The four built-in report templates (spec 2026-09-26-reports section 6.2; index fixed ids).

Catalogue migration 0002 seeds a frozen copy of this data; tests/test_catalogue_migration_0002.py
pins that the two agree. When the catalogue is unavailable, R1 serves these from code. A built-in is
duplicated, never edited or deleted. Every config lists all eight sections: the template's own
sections first and enabled, the rest after them in canonical order and disabled (plan R0 rulings 2
and 13). Filters are portable: no data items, no logo, no report date.
"""

from datetime import UTC, datetime

from app.reports.schemas import SECTION_KEYS, ReportConfig, ReportTemplate, SectionKey

BUILTIN_FULL = "builtin-full"
BUILTIN_FINDINGS_SUMMARY = "builtin-findings-summary"
BUILTIN_SURVEY_COUNTS = "builtin-survey-counts"
BUILTIN_VOLUMES = "builtin-volumes"
BUILTIN_IDS = (BUILTIN_FULL, BUILTIN_FINDINGS_SUMMARY, BUILTIN_SURVEY_COUNTS, BUILTIN_VOLUMES)
SEEDED_AT = datetime(2026, 9, 30, tzinfo=UTC)


def default_config() -> ReportConfig:
    """A new report's config: every section on, in canonical order, with default options."""
    return ReportConfig()


def _config(on: tuple[SectionKey, ...], options: dict[SectionKey, dict] | None = None) -> ReportConfig:
    base = {s.key: s for s in ReportConfig().sections}
    sections = []
    for key in [*on, *(k for k in SECTION_KEYS if k not in on)]:
        update: dict = {"enabled": key in on}
        if options and key in options:
            update["options"] = base[key].options.model_copy(update=options[key])
        sections.append(base[key].model_copy(update=update))
    return ReportConfig(sections=sections)


def _template(id_: str, name: str, description: str, config: ReportConfig) -> ReportTemplate:
    return ReportTemplate(
        id=id_,
        name=name,
        description=description,
        builtin=True,
        config=config,
        created_at=SEEDED_AT,
        updated_at=SEEDED_AT,
    )


BUILTIN_TEMPLATES: list[ReportTemplate] = [
    _template(
        BUILTIN_FULL,
        "Full inspection report",
        "Every section: cover, summary, findings table, a page per finding, measurements,"

        _config(SECTION_KEYS),

        BUILTIN_FINDINGS_SUMMARY,

    The four built-ins (`builtin=True`, fixed ids from app/reports/templates/builtins.py) are seeded
