## Why

The operator asked for an AI agent inside a project that can use the app's own capabilities from
plain language ("label the first 500 images with these classes"), driven by their own OpenAI or
Anthropic key. Running the loop in the sidecar is what keeps keys in Credential Manager, and
dispatching tools through the existing HTTP routes is what keeps validation, background jobs and
websocket events identical to the UI's.

## How to test

1. Open Kestrel AI (already installed from this build) and open a project, e.g. Ahmadia.
2. In App settings, confirm a key is stored for OpenAI or Anthropic.
3. Click **Project agent** in the header. The drawer opens with a provider picker showing e.g.
   `gpt-5 · Ready`, three example prompts, and a message box.
4. Ask something read-only first: "How many images still have unreviewed suggestions?" Expect a
   tool row (Find images) and an answer with real numbers.
5. Ask: "Label the first 20 images with excavator and dump_truck." Expect the agent to add the
   missing class, then an **Approval needed** card naming the images, requests and an estimated
   cost in USD.
6. Click **Deny** — the turn ends and nothing is charged. Repeat and click **Approve** to run it:
   a Detect job appears in the Jobs panel with progress, and the suggestions land in Review.
7. Press **Stop** during a turn: the turn stops, and any job it already started keeps running and
   stays cancellable in the Jobs panel.
